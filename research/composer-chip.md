# Composer chip

`#gear-btn` remains the composer control. `openGearPopover` opens the model picker directly from it; the rail gear keeps its app menu. `renderGearApp(target)` supplies the same purpose, Remote Control and Settings actions to VS Code's `+` menu, where each group has a heading. Rail surfaces keep their upload-only `+` menu.

`syncModelChip` shows the existing provider glyph, model name, effective effort and chevron. `renderEffortStrip` uses the model's advertised ladder, with the existing fallback ladder for older metadata. Rail and gradient fill occupy the same box; `clip-path` reveals a slice instead of compressing the gradient. The knob interpolates the same palette anchors. The model list is the only scroller; effort and Manage providers stay pinned. Selection can lock while the chip and provider recovery remain actionable.

Effort is optimistic and reconciles on the next `initialState` — the same promise the effort dots kept before the chip. `setEffort` deliberately sends **nothing** back: `emit` both buffers into the session replay and fans to every remote holding the conversation, and `initialState` is action-shaped there (`restoreRememberedRemoteSession` posts `resumeSession` from it), so acknowledging with that frame made a phone clear and replay its own transcript and drop an in-flight recording on every effort or model change. The residue, stated plainly: dismiss the restart prompt and the chip shows the level you picked until the conversation next reloads. `test/mode-prefs.test.ts` pins the silence.

Model metadata supplies effective effort when advertised. An older host with no effective-effort metadata gets no guessed chip word; the strip says Default until the host supplies the value. An incompatible model ladder resets to the advertised effort and announces the change — client-side, from `modelChanged` alone.

The `--e1`–`--e4` ramp is fixed hex in `:root` with a `body.vscode-light` override, matched byte for byte by the desktop shim and the relay page so one effort is one colour everywhere. That selector does not match VS Code's High Contrast Light, so the strip renders the dark ramp there — a regression against the old dots, which took `--vscode-button-background` and so followed any theme. Accepted knowingly rather than half-fixed: the stylesheet's whole light-override system already sits behind the same selector (the diff add/delete/read/modify palette among it), no gate covers HC Light, and serving this one control there while the rest stays dark is the worse of the two states. `npm run e2e:hc-colour` covers HC **dark**, where the knob reads at 5.89:1.

The donut's own numbers are the ladder's first rung, above the mode word: they are the one readout here nothing in the message depends on, and the tooltip and popover both still carry them. Wide non-touch surfaces keep them; touch drops them outright, as it did before the chip existed. Below a 250px card on touch the donut itself goes — six controls at a 36px tap floor need more room than that rung has, and a control too small to hit is worse than one honestly absent. Its touch rules live in the later coarse-pointer block beside `#donut-label`, not in the composer's own: `.context-donut` is declared further down this stylesheet at the same specificity, so an earlier copy is simply overwritten.

The existing `.composer-card` inline-size container is intentional: fixed rail popovers are its siblings, so their containing block stays unchanged. It measures the card content box after the outer composer's gutters and card border. A measured 334px VS Code composer has a 324px query box. Mode text drops at 430px, effort at 300px, model text is capped at 272px and drops at 224px. Touch always hides effort, caps the model name at 296px and drops it at 250px. Long model names also use ordinary flex ellipsis.

The mic node is immediately after `+` in `.toolbar-left`. New host markup puts it there; renderer startup moves the existing node for older shells. The textarea and highlight share symmetric 8px horizontal padding. Voice states retain their existing classes and animations.

`contextFullnessColor` serves both the donut and the single context bar. Thresholds are strictly greater than 70 and 90 on the rounded percentage. Both purposes reveal the bar and secondary Compact button; the coding ledger remains below them.

## Verification

- `test/composer-chip.dom.test.ts`: direct picker, signed-out recovery, advertised efforts and keyboard controls, reconciliation, flat app-menu sequences and context thresholds in both purposes.
- `test/mode-prefs.test.ts`: host reconciliation on success, refusal, priming and cancelled restart for the existing message contract.
- `npm run e2e:composer`: Chromium renders shipped markup, scripts, CSS and palettes across four surface fixtures, two themes and nine widths, including the desktop shell's wrappers and spacing. It measures rendered text and ancestor clipping at 334px, each collapse rung, real truncation, all toolbar controls, mic padding/size, pinned scrolling, matching rail/fill boxes, reduced motion and visible context controls. Screenshots and measurements are in `.screens/composer/`.

The browser fixtures use this repository's shared renderer and owned palette; they do not load the relay's downstream page overrides. The relay half landed alongside this one: `syncRemoteUploadRows` now finds `[data-upload-row="photo"]` and inserts Add document directly after it, the page's own composer markup matches this one, its 46px/8px mic-lane overrides and dead `.effort-dot`/`.model-name-btn` rules are gone, it carries the same effort ramp in both themes, and `scripts/touch-ui-check.mjs` asserts the deleted lane on the surface that actually had it.
